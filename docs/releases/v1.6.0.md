# v1.6.0 — the retrieval path, measured and halved (M22)

**Tag:** `v1.6.0` · **Milestone:** M22 · **Requirements:** NFR-01, NFR-14 · **Plan:** [18](../18-performance-plan.md)

## The result

| arm | mean | p95 | qps | `fold_plural` calls/query |
|---|---|---|---|---|
| before (`v1.5.0`) | 0.755 ms | 1.469 ms | 1,324 | 564 |
| after | 0.342 ms | 0.797 ms | 2,924 | 138 |

**2.21× on the mean, 1.84× on p95**, with **identical** answers on all eight benchmark questions:
same text, citation, confidence and refusal decision. The benchmark fails if the two arms ever
diverge, which is what stops a speedup from being a behaviour change.

The arms alternate across three repeats and the table is the median run; separate invocations of
the script measured 2.0×–2.9× (the top of that range is a run that shared the machine with other
benchmarks). The direction is stable, the point estimate is not, and both are reported.

## What was actually slow

The M5 profile cached chunk token sets for the *reranker* and left the *gate* re-tokenising the
winning passage on every request. That was **71% of query CPU**. `Reranker.coverage_of_tokens` now
does the same arithmetic over the cached sets.

Two smaller items, both removals:

- `diagnose` re-embedded the query that `_dense_search` had already embedded. One vector is now
  computed in `diagnostics` and shared.
- `tokenize` called `fold_plural` twice per word, once to build the token and once to test the
  stopword list.

## What this release adds to the API

- `timings.retrieval` in every answer: `embed_ms`, `bm25_ms`, `dense_ms`, `fuse_ms`, `rank_ms`,
  `cosine_ms`, `coverage_ms`. Nested, so `serialize_ms` cannot double-count a sub-stage as a
  top-level one — the M5 negative-`serialize_ms` bug, structurally prevented this time.
- The contract probe now **requires** that breakdown, so NFR-14 is a contract rather than a claim.

## What it does not change

Recall@10 0.9167 · refusal 1.0000 · temporal 9/9 with 0 future leaks · determinism 0 differences ·
159 tests · 35 files within the 200-line ceiling. No threshold, ranking rule or refusal decision was
touched: this phase removes repeated work.

## Code shape

Three new modules, each one responsibility: `retrieval/confidence.py` (the gate's arithmetic),
`retrieval/windows.py` (the date mask), `retrieval/passages.py` (ranked index → citable passage).
`ATLAS_PERF_NAIVE=1` restores the old path so the benchmark can measure both arms in one run; the
shipped default never selects it.

## Carried forward

`docs/18` M23–M27: admission control (the only phase that changes a **failed** requirement), worker
processes, caching, incremental index updates, and the FR-17 query-expansion experiment.
`docs/17` L19 records the limit of this evidence: one laptop, one corpus, a ratio rather than an
absolute.
