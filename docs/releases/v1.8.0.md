# v1.8.0 — the bound under real concurrency, and worker processes (M23.1, M24)

**Tag:** `v1.8.0` · **Milestones:** M23 follow-up, M24 · **Requirements:** NFR-01, FR-20 · **Plan:** [18](../18-performance-plan.md)

## The bound, finally binding

`results/overload.md` runs the server deliberately under-provisioned — 4 slots, 8 waiters, 25 ms of
waiting, 40 ms injected per answered request, 50 client processes — so the admission bound is
reached by load instead of only by unit tests:

| metric | value |
|---|---:|
| requests offered | 2,000 |
| served (200) | 321 |
| shed (`503 OVERLOADED`) | 1,679 |
| **shed rate** | **83.95%** |
| served p50 / p95 / p99 | 54.06 / 79.05 / 111.77 ms |
| shed p95 | 37.02 ms |
| transport failures | 0 |
| admission `rejected` in `/v1/metrics` | 1,679 |

Two things this proves that the unit tests could not:

- **the counters agree with reality** — 1,679 rejections counted, 1,679 503s observed;
- **liveness survives it** — with every slot held, `/v1/ask` answered `503 OVERLOADED` with
  `Retry-After: 1` in 30.05 ms while `/v1/healthz` answered `200` in 15.91 ms.

Shedding is **bounded, not instant**: a refused request pays the configured wait before the 503,
which is why its p95 is 37.02 ms and not ~1 ms. `ATLAS_ADMISSION_WAIT_MS=0` refuses immediately,
and the unit test covers that path. The 84% shed rate is *configured*: at the shipped 32 slots no
measured load sheds at all, which is the honest reading and is now L3.

## Worker processes

`atlas.cli serve --workers N` runs N processes behind one listening socket.

| workers | p50 | p95 | rps | pids observed |
|---|---:|---:|---:|---:|
| 1 | 10.59 ms | 24.96 ms | 378 | 1 |
| 2 | 5.18 ms | 11.08 ms | 437 | 2 |
| 4 | 2.50 ms | **5.10 ms** | 587 | 4 |

p95 falls **4.9×**; throughput rises only **1.55×**, and the report says why: at a fixed ten users
offering one request at a time, the client caps total throughput long before the workers do. What
the extra processes buy at this load is less queueing, not more work done. Near-linear throughput
stays unmeasured and needs a client machine.

The plan specified `SO_REUSEPORT`. Windows does not have it, so the shipped form is the portable
one: the parent creates the socket, each child inherits it (`WSADuplicateSocket` on Windows, fd
inheritance on POSIX). One port, one accept queue — the contract is unchanged.

## Configuration

The bound is now operator-configurable, and a malformed value refuses to start with the variable
named:

| variable | default |
|---|---:|
| `ATLAS_MAX_INFLIGHT` | 32 |
| `ATLAS_MAX_WAITING` | 64 |
| `ATLAS_ADMISSION_WAIT_MS` | 25 |

These read the environment **per instance** (`default_factory`), because a dataclass default is
evaluated once at import and would freeze the environment before a test or a benchmark could set it.

## What else changed

- `src/atlas/status.py`: the liveness and metrics payloads moved out of `handler.py` when the
  admission block pushed it past the 200-line ceiling. `pid` joined the health payload so a caller
  can tell which worker answered.
- The overload run's latency padding was an `ATLAS_SLOW_MS` setting in the answer path. It was
  removed after the tag: `bench/overload.py` now wraps the answer function inside its own process,
  so a refused request still pays nothing for the work it was refused and `src/` carries no
  latency knob at all.

## What it does not change

Frozen sets: recall@10 0.9167, refusal 1.0000, temporal 9/9 with 0 future leaks, determinism 0
differences, contract 15/15. 176 tests, 38 files within the ceiling.
