# Atlas v1.4.0 — release note

**Tag:** `v1.4` · **Previous:** `v1.3` · **Date:** M20 · **Scope:** API contract, enforcement, close-out

This release does not change what the product answers. It changes whether you have to take the
project's word for it: the API now matches its specification, the structural and traceability claims
are tests, and the README opens with what is proven next to what is not.

## Added since v1.2

- **`POST /v1/ask`, `GET /health`, `GET /v1/metrics`** (M18, FR-20). The body contract is strict:
  an unknown field is a 400, because a misspelled `query` must not answer an empty question.
  Metrics are per-route counters and a 1000-request latency window, with no request content stored.
- **`results/api_contract.md`** — twelve probes against a live server over a freshly ingested
  corpus, four of them documented failures. `make api-contract`.
- **`tests/test_architecture.py`** (M19, NFR-12) — SwDD §1's layering rules checked on the real
  import graph, relative imports included.
- **`tests/test_traceability.py` + `results/EVIDENCE.md`** (M19, NFR-13) — every FR/NFR id resolved
  to a test, report, ADR or an evidence row that is followed to a file on disk.
- **`results/determinism.md`** (M20, NFR-15) — the eval command run twice, byte-exact, 0
  differences. NFR-15 is no longer exempt from traceability.
- **`docs/17-limitations.md`** — the register of what is not met, not built, or too small to
  generalise.
- **Fusion and phrase-novelty panels** on `dashboard.html`, and `v4` in the holdout tables.

## Changed

- Unknown methods return `405` with the JSON error envelope instead of the stdlib's HTML page
  (FR-23, previously violated in letter).
- `handler.py`, `api.py` and `metrics.py` split out of `server.py`, which keeps one responsibility
  and stays under the 200-line ceiling.
- FR-20 amended: `POST /v1/documents` is not offered (ADR-0012). Ingest stays a CLI operation.
- `README.md` restructured: proven claims in a table, unproven ones named underneath.

## Upgrade notes

Additive: no route was removed and no response field changed. A client that only calls
`GET /v1/ask` needs no change. If you were relying on the stdlib's HTML error page for an
unsupported method, that is now `{"error": {"code": "METHOD_NOT_ALLOWED", …}}` with status 405.

## Known issues

Unchanged and named: FR-17 (the refusal gate does not generalise) and FR-11 in its amended form.
See [`docs/17-limitations.md`](../17-limitations.md) — L1 and L2 are the two to read first.
